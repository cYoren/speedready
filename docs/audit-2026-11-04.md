# Speedready audit and remediation, 4 November 2026

## Implementation integrity verdict

**Pass within the tested scope.** The reader retains its established reading surface, theme tokens, library, and optional language-learning controls. The added import/download modules have explicit failure handling. The Impeccable source detector returned no findings after the fixes.

This audit began from local commit `e05a7af`. It includes the shared web reader, Linux GTK implementation, download endpoint, and Android/iOS integration points. Publishing was held throughout.

**17 verified findings addressed: 1 P0, 11 P1, and 5 P2.** No confirmed blocker remains open in the exercised local flows. Deployment and native-device validation remain release gates, described below.

## Verified fixes

### [P0] F01: Reading progress outruns the visible text

- **Location:** `web/index.html:826`
- **Impact:** A long book stopped showing its current word after the initial 2,040-word render. A single very long paragraph also defeated the previous page-boundary logic.
- **Fixed:** Rendering now follows the current reading position with a bounded amount of preceding text, including mid-paragraph positions. Keyboard focus follows the newly rendered current word.
- **Verification:** A 16,000-word synthetic book was exercised at positions 2,700 and 15,999, with visible highlight and focus assertions.

### [P1] F02: Valid EPUB metadata and navigation were misread

- **Location:** `web/epub.js:50`
- **Impact:** Regexes required particular namespace prefixes and double quotes, so valid books could fail to open or lose their title/language. Nested text outside inner paragraphs could disappear. The native reader could choose landmarks instead of the table of contents.
- **Fixed:** Added an XML-based EPUB reader, preserved direct and nested text, decoded metadata entities, and selected the navigation explicitly marked as the table of contents in both readers.
- **Verification:** A compressed EPUB with single quotes, prefixed XML namespaces, an entity in its title, multiple navigation sections, nested prose, and a three-letter language code passes browser and Python checks.

### [P1] F03: ZIP inflation had no text-size bounds

- **Location:** `web/epub.js:10`
- **Impact:** Malformed archives and extremely expanded text entries could consume excessive memory or produce unhelpful exceptions during import.
- **Fixed:** Validated directory and local entry offsets, compression/encryption support, and expanded entry sizes. Added 40 MB per text entry and 120 MB total expanded text bounds to both EPUB readers; web EPUB input is capped at 150 MB.
- **Verification:** Invalid/truncated archive rejection is covered by Node checks; normal compressed fixtures still import. These bounds do not constitute a complete archive fuzzing audit.

### [P1] F04: Buffered downloads exceeded the hosting response limit

- **Location:** `api/book.js:45`
- **Impact:** The previous endpoint collected the entire book before returning it. Books above the hosting platform’s buffered response limit could pass local tests and fail after deployment.
- **Fixed:** Streams validated bytes with backpressure, a total timeout, client-disconnect cancellation, and the existing 30 MB bound. Unsafe redirects and invalid content remain rejected. Configured a 60-second function duration.
- **Verification:** A controlled 6 MB response starts reaching the client before its upstream has finished. Empty files, split format signatures, unsafe redirects, HTTP method restrictions, and charset preservation are checked. Deployment behavior still needs a live smoke check.

### [P1] F05: Settings and dialogs had keyboard and screen-reader gaps

- **Location:** `web/index.html:1129`
- **Impact:** Settings used non-focusable divs as switches, the add-files label lacked a keyboard action, dialogs did not contain focus, and touch users had no persistent close control. Zoom and reduced-motion preferences were restricted. Android forced system text zoom to 100%.
- **Fixed:** Added native switch buttons with announced state, a real add-files button, dialog labels, focus containment/restoration, persistent close controls, keyboard access to the current word, status announcements, zoom support, and reduced-motion behavior. Android Back now uses the same dialog cleanup; Android honors system text scaling.
- **Verification:** Chromium keyboard and synthesized-touch checks pass. Axe reports zero WCAG-tagged violations in the tested catalog/settings states in both themes. Android Java compilation passes. Physical VoiceOver/TalkBack testing remains required (WCAG 1.3.1, 1.4.4, 2.1.1, 2.4.3, 4.1.2 are relevant).

### [P1] F06: Failed imports could replace a readable book

- **Location:** `web/index.html:1193`
- **Impact:** An empty text file could become the current web book with an invalid position. A failed desktop import cleared the current book even when its old content remained visible.
- **Fixed:** Reject empty parsed books before changing the active book and preserve the desktop book when the next import fails. Clamp saved positions to valid integer indices.
- **Verification:** Browser empty-import regression and Python failed-import tests preserve the previous book.

### [P1] F07: Offline-save failures were silently swallowed

- **Location:** `web/index.html:1535`
- **Impact:** A readable import could appear to be saved when IndexedDB or library-index storage failed, leading to a missing book after restart.
- **Fixed:** Continue reading the import while clearly announcing that it could not be retained offline. Library-index writes now report failure. Language changes also surface persistence errors.
- **Verification:** A simulated IndexedDB quota error produces a recovery message while leaving the book readable.

### [P1] F08: An optional dictionary failure blocked reading

- **Location:** `web/index.html:1268`
- **Impact:** Failure to load the bundled dictionary stopped startup, including access to books that did not require that dictionary.
- **Fixed:** Startup can continue with an empty dictionary and open the book. Legacy learning-data migration waits for a known dictionary source language.
- **Verification:** A browser context with the bundled dictionary returning HTTP 503 and remote dictionary requests blocked still opens the starter book.

### [P1] F09: Desktop vocabulary marks leaked between languages

- **Location:** `speedready.py:1256`
- **Impact:** A word marked as unknown in one language could be treated as unknown in another language with the same spelling.
- **Fixed:** Store desktop learning marks as language:lemma and consult them through a language-aware helper. Legacy bare marks retain the original German scope.
- **Verification:** Python language-isolation checks and an isolated GTK window exercise independent marks across languages.

### [P1] F10: Dark-mode action link failed text contrast

- **Location:** `web/index.html:37`
- **Impact:** The source-code action inherited the browser’s blue link color on a dark panel; axe measured approximately 1.82:1 contrast. Gender colors also needed a readable foreground while the current word is highlighted.
- **Fixed:** Button-style links inherit the theme foreground. Highlighted text uses a readable foreground and the light-theme green was darkened.
- **Verification:** Axe finds no contrast violations in the tested catalog/settings states in either theme. WCAG 1.4.3 applies.

### [P2] F11: Catalog queries repeatedly normalized the full collection

- **Location:** `web/catalog.js:4`
- **Impact:** Desktop searches took approximately 0.88–0.99 seconds per query, and web queries repeated normalization of all 78,461 records.
- **Fixed:** Build normalized search indexes once. Browser indexing yields between batches, and language-specific searches use a smaller candidate set.
- **Verification:** Measured native query time dropped to approximately 46 ms. Browser queries measured approximately 9–12 ms including the browser round trip. These are workstation measurements, not low-end-device guarantees.

### [P2] F12: Long words could overflow reading surfaces

- **Location:** `web/index.html:166`
- **Impact:** Long tokens could be clipped by the pacer or overflow the RSVP display on a narrow screen.
- **Fixed:** Bound word cells and glosses to their available width and allow long RSVP words to wrap.
- **Verification:** A 175-character synthetic word remains within the phone RSVP surface. Phone/tablet/desktop screenshots were inspected.

### [P2] F13: iOS folder discovery omitted PDFs

- **Location:** `ios/Speedready/App.swift:86`
- **Impact:** The shared reader accepted PDFs, but finding books in an iOS folder listed only EPUB and text files.
- **Fixed:** Include PDFs in the folder extension filter.
- **Verification:** Source inspected. This Swift change has not been compiled on a Mac in this audit; include it in the next simulator/device validation.

### [P2] F14: Privacy copy contradicted selected book downloads

- **Location:** `web/privacy.html:43`
- **Impact:** The page said nothing the user reads or looks up ever leaves the device, which did not describe the new download service or chosen external links accurately.
- **Fixed:** Explain local catalog search and storage, the book identifier/download URL sent when requesting a book, ordinary source/hosting network information, and user-selected external links.
- **Verification:** Copy checked against the request and storage paths in the implementation.

### [P2] F15: Removing the active desktop book immediately re-added it

- **Location:** `speedready.py:977`
- **Impact:** Removing the current library entry called save, which wrote that same active book back into the library.
- **Fixed:** Stop reading, clear the active book’s views and last-book pointer, remove its entry, and save the remaining library.
- **Verification:** An isolated GTK window opens a fixture, removes the active entry, and verifies that both the entry and last-book pointer stay removed.

### [P1] F16: Unicode text and source encodings could be corrupted

- **Location:** `web/reading.js:28`
- **Impact:** Text import assumed UTF-8. UTF-16 books and direct text downloads in another declared charset could lose characters.
- **Fixed:** Recognize UTF-16 byte-order marks, retain text download charset information, decode it in the web reader, and normalize native text downloads to UTF-8.
- **Verification:** Japanese UTF-16 and UTF-8 BOM checks pass. A controlled ISO-8859-1 café download retains its characters through the HTTP endpoint and native download path. Undeclared legacy encodings remain dependent on source metadata.

### [P1] F17: Large text paragraphs overflowed the JavaScript call stack

- **Location:** `web/textclean.js:50`
- **Impact:** Passing every word as a separate argument to push caused a RangeError for sufficiently large paragraphs.
- **Fixed:** Append tokens iteratively in both plain-text parsing and cleanup.
- **Verification:** A 160,000-word single paragraph now parses successfully in the Node regression check.

## Release gates and limits

1. **Live website/API smoke check after deployment:** local streaming tests cannot prove hosting configuration or runtime behavior. Vercel documents a 4.5 MB buffered-response limit and recommends streaming for larger responses: [official guidance](https://vercel.com/kb/guide/how-to-bypass-vercel-body-size-limit-serverless-functions). Confirm a real hosted download, including one above that threshold, before publishing mobile packages.
2. **Apple build validation:** compile the small Swift PDF-filter change on the Mac, then test folder discovery and imports in the iOS shell. No signed iOS build was created here.
3. **Physical-device pass:** VoiceOver/TalkBack, system text size, keyboard/IME insets, Android Back, iOS folder permissions, speech voices, and interruptions should be exercised on devices before store submission. Android Java compilation is not an end-to-end device test.
4. **Known product boundaries:** dictionary glosses cover the existing ten languages; speech depends on device/installed voices. Image-only PDFs need OCR outside this app. Book availability, declared text encodings, source restrictions, and the catalog snapshot remain source-dependent.

## Follow-up, 9 November 2026

### Regressions from this audit, fixed

- **Glosses were hidden while the gloss setting was on.** The new styling rule at `web/index.html:65`
  dropped the `body.plain` scope and hid every translation unconditionally, so “Translation above the
  words” appeared broken across the web reader and its packaged shells. Restored the scope
  (`body.plain .c .g{display:none}`) and added a browser assertion that a translation is visible with
  the setting on and hidden only with it off.
- **The marker that keeps non-text out of a book was split off in unspaced scripts.** For Chinese or
  Japanese, the parser prefixes a marked span with `\x00`; tokenization separated the marker from the
  second character, so `Book.clean()` removed the marker and kept the page title as reading text.
  `reading.tokenize` and `web/reading.js` now keep the mark on every piece of a marked span, with a
  Python regression test (`tests/test_reading.py`).

### Web and desktop gloss selection now agree (gap 7)

`tools/export_web.py` no longer chooses a gloss by source priority alone. It calls
`speedready.pick_gloss`, the scoring `Gloss.raw` uses, and stores the surface forms whose scored
answer differs from their lemma's (`s` in the exported dictionary; 4,715 of them), because the desktop
scores a word and its lemma separately.

`web/dict-de-pt.json` was regenerated from the published `packs` release asset
(`gloss-de-pt.sqlite`, built 2026-10-01), not from the local cache, which predates the 1.0.4 licence
fix and still carries MUSE rows that this project does not distribute.

Agreement over `web/starter-de.json` (26,946 words, 7,077 distinct), the web reader's own lookup
against `Gloss.raw` on the same pack, measured with the same code before and after:

| | words | distinct |
|---|---:|---:|
| before (dictionary from `master`) | 96.88% | 94.43% |
| after | 99.97% | 99.87% |

Nine disagreements remain, in two classes:

- four lowercase spellings of nouns (`zuviel`, `floß`, `schoß`), where the desktop's lemma fallback
  also tries `capitalize()` and the web reader's does not;
- five tokens whose punctuation differs between the two `strip()` implementations (`[_»Schild«`):
  the desktop's `\W` keeps the underscore, the web reader's letter/number class removes it, so the
  web reader glosses a word the desktop leaves alone.

`python tools/export_web.py --check` reproduces the table and exits non-zero below 99%.

Note: the “93.3 percent” figure in the old `TODO.md` no longer reproduces; the dictionary was rebuilt
after it was written and the commonest function words now come from `core/`. The pair above is
measured with today's data, not tuned to match the old number.

### Function words (gap 6)

The three documented failures were already fixed by `core/` and its English pivot, and are now pinned
by `tests/test_core.py`: `de→es wollen` = “querer”, `sv→de är` = “ist; sind”, `nl→pt is` = “é”.
Verified against the published packs, and the README no longer describes the fix as pending.

### Release guard (gap 9)

`tools/check_release_tag.py` fails a tag whose `versionCode` does not increase over the previous
release tag, whose `versionName` disagrees with the tag, or (`--strict`) whose fdroiddata metadata is
behind it. `tools/make_release_apk.sh` runs it before building. Run over this repository's history it
trips on exactly one tag: `v1.0.2`, which shipped as versionName 1.0.1 with versionCode 2 unchanged —
the failure mode the guard exists for. `tests/test_release_tag.py` holds the rules and that history.
